# BRIEFLY — BI와 핵심 UX 3방향

2026-10-23 · 방향 비교용 인터랙티브 프로토타입

같은 브리핑을 세 가지 브랜드와 첫 화면에 적용했다. 모바일은 390px, 웹은 1440px를 비교 기준으로 삼았다. 현재 Flutter 앱이나 백엔드와 연결한 구현이 아니라, 디자인 결정을 위한 독립적인 HTML/CSS/JS 프로토타입이다.

## 비교판 열기

저장소 루트에서 실행한다.

```powershell
python docs/revision/bi-exploration/serve.py --port 8766
```

브라우저에서 `http://127.0.0.1:8766/`을 연다. 모바일 3안, 웹 3안, 모바일 + 웹 보기를 전환할 수 있다. 각 안의 ‘직접 사용해보기’ 링크는 브라우저 폭에 맞춰 동작하는 원본 화면을 연다. 후보 표시와 이슈 저장은 이 브라우저에만 남는다.

서버는 로컬 주소에 바인딩하며 이 폴더의 디자인 파일과 저장소의 폰트만 제공한다. 브라우저의 실제 기기 상태바·오디오 권한·백그라운드 재생을 구현한 것은 아니다.

## 세 방향의 차이

| 방향 | 브랜드 약속 | BI | 첫 화면과 행동 | 검토할 절충점 |
|---|---|---|---|---|
| A · 데일리 저널 | 조금 더 이해하는 하루 | 접힌 페이지 심벌, 세리프 워드마크, 종이색·잉크·적갈색 | 대표 이슈에 집중해 읽고 출처와 오디오로 이동. 웹은 지면형 편집, 모바일은 대표 이야기 중심 | 신뢰와 맥락이 잘 드러나지만 세 이슈를 모두 훑는 속도는 느릴 수 있음 |
| B · 데일리 라디오 | 오늘의 세상에 주파수를 맞추다 | 소리를 닮은 b 심벌, 두꺼운 산세리프, 버터 옐로·브라운·코랄, 해와 소리의 표지 | 회차 재생이 첫 행동. 웹은 표지와 안내를 나란히, 모바일은 표지를 맨 위에 배치 | 기억하기 쉽고 듣기 진입이 강하지만 첫 이슈가 화면 아래로 밀림 |
| C · 클리어 브리프 | 오늘, 이 세 가지만 | 압축된 세 줄과 재생 기호, 산세리프, 쿨 화이트·포레스트·라임 | 이슈를 먼저 훑고 읽기·듣기를 선택. 웹은 메뉴·본문·회차의 3열, 모바일은 이슈 목록 | 탐색이 빠르지만 브랜드의 감성이나 편집 매력을 더 보강할 여지가 있음 |

제작자 관점의 초기 판단: 읽기와 듣기를 동등하게 연결하는 제품 골격에는 C가 가장 직접적이다. A는 편집 브랜드로 신뢰를 쌓을 때, B는 출근길 오디오 습관을 중심으로 성장시킬 때 강하다. 사용자 평가 전 가설이며 최종 선택은 정하지 않았다.

## 공통 핵심 UX

1. 오늘의 회차를 확인한다: 같은 날짜, 세 이슈, 읽기 2분·듣기 5:12라는 동일한 분량 가설.
2. ‘2분 읽기’에서 세 이야기를 이전·다음으로 읽고 회차를 마친다.
3. 읽던 이슈의 ‘이 구간 듣기’에서 해당 구간으로 이동한다.
4. 플레이어에서 현재 구간을 다시 읽거나 위치를 이동하고 일시정지·닫기 한다.
5. 이슈의 출처를 열고 요약으로 돌아간다. 이슈를 저장하고 저장 목록에서 다시 읽는다.

세 구간은 `0:00–1:44`, `1:44–3:27`, `3:27–5:12`이다. 현재 시각은 초 단위 타이머로 모의 재생하며 실제 음원은 없다. 출처는 자료 유형을 보여주는 가상 예시이며 실제 기사 링크는 없다. 본문은 디자인 검토용 가상 뉴스다. 지난 브리핑에는 비교용 회차 하나만 있다. 완독 기록, 인증, 서버 저장, 실제 모바일 앱 빌드 및 오디오 스트리밍은 포함하지 않는다.

## 검토 방법

- **브랜드 인상:** 첫 5초에 신뢰·친근함·명료함 중 무엇이 먼저 느껴지는가?
- **행동 발견:** 읽기 또는 듣기를 시작하는 위치가 명확한가?
- **연결성:** 읽던 이야기의 오디오 구간과 듣던 이야기의 본문을 쉽게 찾는가?
- **플랫폼 일관성:** 모바일과 웹이 같은 서비스로 보이면서 각 화면의 공간을 잘 쓰는가?

‘어느 안이 예쁜가’와 ‘어느 안에서 매일 브리핑을 끝내기 쉬운가’를 나눠 판단한다. 선택 후 해당 방향의 로고·타이포·색상 토큰과 읽기·플레이어 상세 화면을 확장한다.

## 검수 기록

2026-10-23, Chromium 기반 인앱 브라우저에서 확인했다.

- 세 안 모두 320px / 390px / 1440px에서 문서 가로 넘침 없음.
- A의 읽기 1→2→3 완료, 출처와 본문 왕복, 읽던 2번 구간을 1:44에서 재생, 현재 구간 읽기, 일시정지·닫기 확인.
- B의 모달 버튼 대비, 저장과 저장 목록, 320px에서 플레이어 닫기 확인.
- C의 저장 상태 공유, 2번 구간 시작, 재생 위치를 끝으로 옮긴 뒤 3번 본문 연결 확인.
- 비교판의 모바일·웹·병렬 보기 확인. 모달 스타일의 콘셉트 CSS 충돌과 구간 길이 불일치 수정.

이 확인은 브라우저 프로토타입의 동작 검수다. 실제 기기 접근성 인증이나 사용자 사용성 평가를 대신하지 않는다.

## 이미지 제작 기록

A의 [도시 이미지](assets/city-editorial.png)는 내장 `image_gen` 도구로 생성한 브랜드 분위기용 이미지다. CLI나 외부 이미지 검색을 사용하지 않았다. 실재 사건의 보도 사진이 아니다. B의 소리 표지와 세 안의 심벌은 SVG/CSS로 작성했다.

이미지 생성 프롬프트의 핵심 지시: 차분한 이른 아침의 한국 도시와 강을 멀리서 바라보는 가로형 에디토리얼 사진. 아이보리빛 안개, 은빛 수면, 채도 낮은 녹회색과 은은한 테라코타 색조, 자연스러운 빛과 넉넉한 공간. 글자·로고·UI를 넣지 않는다. 최종 파일은 `assets/city-editorial.png`에 저장했다.
