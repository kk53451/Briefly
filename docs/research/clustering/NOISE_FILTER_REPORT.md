## 1. 문제 정의

### 1.1 현상
BigKinds API에서 수집한 뉴스 기사 중 일부가 **실제 본문이 아닌 페이지 전체 텍스트**를 포함하고 있음.

- 네비게이션 메뉴
- 사이드바 링크
- 푸터 정보
- 관련 기사 목록
- 구독/로그인 버튼 텍스트

### 1.2 원인
1. **언론사별 DOM 구조 불일치**: 수백 개 언론사마다 HTML 구조가 다름
2. **Selector 미지원**: `ARTICLE_SELECTORS`에 정의된 19개 언론사 외에는 본문 영역 특정 불가
3. **Fallback 동작**: Trafilatura 추출 실패 시 전체 텍스트를 반환

### 1.3 기존 필터의 한계
```python
# 기존 필터 조건 (모두 통과하면 유효 기사로 판정)
len(content) >= 300        # 최소 300자
content.count('.') >= 5    # 최소 5문장
is_korean_text(content, 0.7)  # 한글 비율 70% 이상
```

노이즈가 포함된 기사도 위 조건을 쉽게 통과함.

## 4. 필터링 전략

### 4.1 하이브리드 필터 설계

**Phase 1: 구조적 노이즈 탐지**

```python
def is_structural_noise(content: str) -> bool:
    lines = [l.strip() for l in content.split('\n') if l.strip()]
    if len(lines) < 5:
        return False

    short_lines = sum(1 for l in lines if len(l) < 10)
    short_ratio = short_lines / len(lines)
    avg_line_len = len(content) / len(lines)

    # 짧은 줄이 30% 이상 AND 평균 줄 길이 20자 미만 → NOISE
    if short_ratio > 0.30 and avg_line_len < 20:
        return True
    return False
```

**Phase 2: 키워드 기반 노이즈 탐지**

```python
NOISE_KEYWORDS = {
    '닫기', '로그인', '회원가입', '전체메뉴', '오피니언',
    '개인정보처리방침', '청소년보호정책', '인기기사', '최신기사',
    '댓글정책', '구독신청', '뉴스레터', '광고문의'
}

def count_noise_keywords(content: str) -> int:
    return sum(content.count(kw) for kw in NOISE_KEYWORDS)
```

**Phase 3: 종합 판정**

```python
# 기존 필터 통과 후 추가 검사
if is_structural_noise(content):
    return False  # 구조적 노이즈
if count_noise_keywords(content) >= 3:
    return False  # 키워드 노이즈
return True  # 유효 기사
```

### 4.2 임계값 선정 근거

| 임계값 | 값 | 근거 |
|--------|-----|------|
| 짧은 줄 기준 | 10자 미만 | 메뉴/버튼 텍스트 평균 길이 |
| 짧은 줄 비율 | 30% 이상 | OK 기사 최대 5.3%, NOISE 기사 최소 75.3% |
| 평균 줄 길이 | 20자 미만 | OK 기사 최소 49.9자, NOISE 기사 최대 10.7자 |
| 노이즈 키워드 | 3개 이상 | OK 기사 최대 2개, NOISE 기사 최소 5개 |

## 8. 검토한 대안

### 8.1 언론사별 Selector 추가
- **장점**: 정확한 본문 추출
- **단점**: 수백 개 언론사 대응 불가, 유지보수 비용
- **결론**: 주요 언론사만 추가, 근본 해결책 아님

### 8.2 글자수 상한선 설정 (예: 5,000자)
- **장점**: 구현 간단
- **단점**: 긴 정상 기사도 필터링 (false positive)
- **결론**: 구조적 필터가 더 정확함

### 8.3 ML 기반 분류기
- **장점**: 높은 정확도 가능
- **단점**: 학습 데이터 필요, 복잡도 증가, Lambda 리소스 제약
- **결론**: 현재 규모에서는 과도함
